# 界面设计规范

本文记录当前界面约定。产品能力、权限和数据语义分别以 [PRODUCT](PRODUCT.md)、[ARCHITECTURE](ARCHITECTURE.md) 和 [DATA-AND-PROTOCOL](DATA-AND-PROTOCOL.md) 为准。

## 设计依据

2026-10-24 的页面评审覆盖首次设置、登录、激活、恢复、管理概览、机器列表与详情、配置、用户、个人概览、订阅与账号设置。采用用户选定的页面结构，并统一不同参考图中的字体、间距、宽度和组件外观。生成图中的示例数据、文案和控件不能作为新增业务能力的依据。

旧 [Figma 文件](https://www.figma.com/design/IKaSuhU32hlyWYqxPUMUsg) 保留为历史参考；涉及当前实现时，以本文、当前代码和真实浏览器验证为准。

## 组件、字体与颜色

- 使用 `@cloudflare/kumo` 的原生 npm exports，包括 Sidebar、Table、LayerCard、Tabs、Dialog、Input、Button、Badge、Meter、Collapsible 和 Chart。任务进度使用 `@cloudflare/kumo/primitives/progress`，保留 progressbar 语义；Meter 用于额度或资源占用。不要复制安装或重写这些组件。
- Kumo 的颜色、圆角、ring、阴影、焦点与交互状态保持原生。只为页面组合、尺寸和响应式布局增加 CSS，不用全局 `table`、`th`、`td` 或泛化选择器覆盖组件内部样式。
- 英文使用 Inter，中文使用 Noto Sans SC。正文、默认输入与表格为 16px / 24px，辅助信息和紧凑控件为 14px / 20px；页面标题为 28px / 36px semibold，分区标题为 20px / 28px semibold。上述 CSS 字号使用 rem，按默认 16px 根字号换算，不锁定浏览器根字号。数字使用等宽数字，代码使用等宽字体；Monaco 为 15px / 24px，图表标签为 14px。不额外调整字距。
- 颜色采用 Kumo 语义 token；状态同时使用文字，不能只依赖颜色。图标使用 Phosphor，图表展示真实统计数据。
- 间距以 4、8、12、16、24、32px 为主。先用标题、间距和分隔线组织信息，避免嵌套装饰卡片。

`app/globals.css` 导入 Kumo 的 Tailwind 主题与 Tailwind，并保留 `@source "../../node_modules/@cloudflare/kumo/dist/**/*.{js,jsx,ts,tsx}"`。通用布局放在 `components/workspace.css`；各领域的布局放在相应的 CSS 文件中，由全局入口统一导入。

Kumo 2.15.0 的默认 `text-base` 为 14px、`text-sm` 为 13px、`text-xs` 为 12px。本应用采用较大的阅读字号，在主题导入之后通过 Tailwind 的公开 `@theme` 机制统一设置 `--text-base` 为 1rem、`--text-sm` 和 `--text-xs` 为 0.875rem、`--text-lg` 为 1.125rem，并设置对应行高；不通过缩放根元素或覆盖组件内部选择器放大界面。控件尺寸仍使用 Kumo 的公开 size 属性。[Kumo 主题](https://kumo-ui.com/colors)、[Tailwind 主题覆盖](https://tailwindcss.com/docs/theme#overriding-the-default-theme)。

字号按内容角色选择，不把任一设计系统的默认值当作通用最低标准。[web.dev 排版教程](https://web.dev/learn/design/typography)建议使用相对单位，并结合行长、行高和缩放检查可读性；[GOV.UK 正文规范](https://design-system.service.gov.uk/styles/paragraphs/)采用 19px 正文和谨慎使用的 16px 小字号，作为可读性参考。[WCAG 2.2 的文字缩放要求](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)关注放大到 200% 后仍可阅读和操作，并未规定统一的最小像素字号。字体调整后检查表格、表单、按钮、弹窗与编辑器，不能只检查 body。

## 页面框架

顶部栏高 56px，侧栏默认宽 260px。管理导航与个人空间分组保留，当前路由有选中状态。760px 以下使用 Kumo 的移动侧栏，导航后关闭，所有导航入口仍可用。

所有面板页面共用 `.page-frame`：宽度占满可用区域、最大 1200px，在侧栏以外的区域居中。`.page-content` 提供桌面 32px、移动端左右 16px 的留白。页面标题与页面内容的外边界一致，账号、概览、列表和编辑页不自行改变主页面宽度。配置表单可在共同边界以内采用居中的 800px 内容列。根文档预留稳定的滚动条空间，避免长短页面切换横移。

布局应覆盖 1920px、1440px、1100px 和 390px。双栏按可用宽度转为单栏；长标识可以换行，表格在自己的容器内滚动，不能撑宽整页或隐藏主要操作。

## 表格与弹窗

表格使用一层 `LayerCard`（`p-0`）包裹原生 `Table`。标题、说明和工具栏放在外侧无边框的布局容器中，避免再套一层卡片。数字列右对齐，身份与状态仍可在窄屏阅读。手机可将次要列移至名称下方或详情区，但操作和业务信息仍需可达。

弹窗使用 `Dialog.Root`、`Dialog`、`Dialog.Title`、`Dialog.Close`；危险确认采用 `role="alertdialog"`。弹窗在视口内居中，保留 Kumo 的原生外观、遮罩、焦点限制、Esc 和关闭后的焦点恢复。最大高度为视口减 32px，长内容在弹窗内部滚动。桌面内边距 32px，窄屏 24px；标题 24px，关闭按钮在右侧。操作区右对齐，取消在前、主要操作在后，间隔 8px。

按需挂载的弹窗先以关闭状态挂载，再进入原生开启动画。提交中禁用重复操作，失败保留输入。取消或关闭不执行危险操作。

## 认证与账号

首次设置、登录、激活和恢复采用同一套居中的 880px 双栏框架：左侧说明当前状态及替代入口，右侧完成表单；640px 以下按阅读顺序堆叠。

登录默认显示用户名和后备密码输入，Passkey 保留独立入口。首次设置只在空实例开放；激活和恢复保留一次性链接、密码设置、可选 Passkey 以及错误状态。密码要求由现有服务端规则决定，界面不增加额外限制。

账号设置按 Passkey、后备密码和 API Key 分区，使用左侧说明、右侧操作或表格的结构，窄屏转单列。最近身份验证、凭据撤销、一次性 API Key 展示和复制失败反馈保持一致。

后备密码的状态标记与修改按钮在同一行垂直居中。账号凭据表的数据行最小高度为 56px，表内操作使用 Kumo 小号按钮并靠右；这是本应用的密度约定，Kumo Table 本身按内容与单元格内边距决定行高。密钥前缀单行省略并保留完整前缀提示，避免仅因标识换行抬高整行。长名称和手机端附加信息仍可自然增加行高，空状态不按数据行压缩。

## 概览与用量

个人概览采用一行三个指标，展示本月已用、本月剩余和今日用量，下方展示趋势及节点用量。管理概览在指标下方组合趋势主区与真实状态驱动的待办辅助区，节点和用户用量表使用完整内容宽度。机器用量以趋势为主，统计摘要为辅助区，下方展示用户分布。

统计保留上海时区、周期选择、上下行、分钟平均峰值、上一周期对比和数据质量说明。无记录显示空状态或未知值，不把缺失统计当作零。估算值、不完整数据、额度警告和刷新失败均在相应数据附近说明。

管理待办来自机器与账号的实际状态：接入机器、安装、配置、失联、核心异常及待激活。每项链接到可处理问题的位置，不增加单独的引导完成标记。

## 机器与配置

机器列表提供名称、地址、地区、标签搜索和连接状态筛选，名称进入详情。连接状态与代理状态分别展示；离线、已卸载、历史数据和进行中的任务不能混为一谈。

详情保留「概览、用量、操作记录、接入与维护」四个 Kumo 标签。选择写入 URL 的 `tab` 参数，支持刷新、直接访问、前进后退和键盘切换。进行中的任务和全局问题在标签之外保持可见。

- 概览先展示 CPU、内存、磁盘剩余和代理连接数，再展示机器信息与配置状态。未知指标显示未上报；网卡累计流量与代理用量分开说明。
- 操作记录采用任务列表与详情检查区。通过明确的选择按钮查看状态、时间、错误、升级恢复结果与诊断日志；窄屏上下排列。多个任务的内容不能串用。
- 接入与维护使用连续设置分区，依次展示版本、机器 Token、安装与绑定、卸载与移除。Token 对有权限的管理员长期可见和可复制。升级说明连接中断；实例替换、Token 重置、卸载和删除记录分别说明后果并保留确认。
- 配置采用居中的连续表单，说明编辑、预览和确认发布阶段。证书来源、端口与完整配置保留原有校验。可选基础 JSON 渐进展开，已有自定义内容或错误时可见。

任何配置输入变更都会使旧预览失效，包括证书来源切换。预览显示有效截止时间，到期后保留输入并要求重新生成。发布后跟踪本次任务与配置版本，只有节点任务成功且实际配置与本次发布一致时显示已应用；失败保留输入并提供重试和日志入口。

## 用户管理

用户表格统一展示身份、角色、额度、状态和操作，下方保留用户与节点用量。创建后通过临时结果展示激活链接。编辑额度、禁用、启用、恢复与重新激活保留权限校验、最近身份验证和确认流程。最后一个启用管理员不能禁用或降级，相关原因在用户附近说明。

## 订阅

订阅列表采用主表格与右侧节点、代理凭据辅助区；窄屏按顺序堆叠。根据草稿、暂停、生成失败和可下载状态展示主要操作，其余操作留在更多菜单。移动端保留名称、状态、节点数和全部操作；达到 20 条上限时说明创建和复制限制。

订阅编辑保留三个原生 Kumo 标签：

- 节点选择：左侧按用途索引，右侧内联选择具名节点。只有明确点击应用才修改草稿；取消选择、切换用途和浏览结果不自动改写筛选。默认 AI/游戏标签和自定义组语义保留。
- 完整 JSON：编辑区与草稿信息辅助栏并列。工具栏提供格式化、查找替换、导入、撤销重做、换行和扩大编辑区。加载时保留尺寸并显示可访问的骨架，不暴露源文本或大块加载文案。
- 节点组属性：原生表格展示组信息，按行展开全部筛选字段。原始输入与稳定绑定标识独立保存，改名、切换标签和删除其他绑定不会错配或丢失内容。

三个标签面板保持挂载，保留 Monaco 实例、撤销历史和字段输入。Ctrl / Command + S 从当前模型保存草稿；格式化保留大整数字面值。语法和 schema 提示不阻止保存草稿，也不替代发布预览。

草稿、预览与已发布版本明确区分。版本冲突保留本地输入，确认后才载入服务器最新草稿。预览过期后重新生成；发布完成提供复制链接、下载配置和客户端导入说明。完整链接和含凭据 JSON 默认折叠，剪贴板不可用时提供可全选的手动复制入口。

暂停、删除和重置凭据保留明确确认；暂停或删除订阅链接不撤销已导入的代理凭据。站内离开、前进后退和关闭页面保留未保存修改保护。

## 验证

真实行为由现有浏览器测试覆盖，包括认证、Kumo 弹窗与导航、机器维护、配置发布、订阅编辑与生命周期、JSON 编辑器、统计和页面布局。布局变化只调整有意改变的定位或交互步骤，不能删除业务断言来使测试通过。

视觉验证使用独立开发数据库和虚构数据，覆盖桌面、窄屏、空状态、加载、错误、确认与成功结果。截图和临时调查资料保存在忽略目录中；运行凭据、本地数据库及生成产物不进入源码提交。
