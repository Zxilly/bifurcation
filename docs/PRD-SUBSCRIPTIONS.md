# 多订阅与 Kumo 一致性 PRD

日期：2026-09-14。状态：设计规格，部分已实现。实现进展：命名多订阅、独立编辑页、加密草稿/发布模板、预览 digest 检查、链接生命周期及节点属性（地区 + 自定义标签）筛选已落地。JSON Patch、发布版本历史、隔离原生核心检查及高级模板升级流程尚未实现；现行边界以产品文档及代码为准。原有仅设计范围描述保留为设计背景。

本文件记录完整目标规格；现行实现仍见 [产品说明](PRODUCT.md) 和代码。与旧版单订阅设计冲突时，以本规格为准。

## 问题与目标

现有「接入与订阅」只有一条用户级链接，无法为桌面、移动端或不同用途分别保存配置。客户端导入需要完整 sing-box JSON，而非仅能连接节点的最小片段。表格和 Dialog 的自定义排版也偏离 Kumo 官方示例。

本轮目标：同一用户创建多条独立订阅；每条订阅保存完整配置模板、节点组绑定和可选 JSON Patch；在发布前预览并校验最终 JSON；统一全站 Table/Dialog 的视觉与交互。仅更新 Figma、需求与参考模板，运行服务、数据库和用户现有订阅不在本轮修改。

## 术语与模型

- **订阅**：用户拥有的一个命名配置及其独立 URL。例如「Windows 日常」「手机」「游戏」。应用名称是帮助用户辨认用途的文字，不代表平台已验证该第三方应用。
- **基础模板**：完整 sing-box 客户端 JSON 的静态部分，包含 DNS、入站、选择组、路由、规则集、实验特性和日志。代理节点及当前用户凭据由平台填入。
- **节点组绑定**：按稳定的组 tag 指定 selector/urltest 的成员来源。绑定规则存于模板旁，不把平台元数据输出到客户端 JSON。
- **JSON Patch**：RFC 6902 操作数组，在基础模板和节点组展开后执行；默认关闭。不运行用户 JavaScript、shell、远程脚本或任意模板函数。
- **已发布版本/草稿**：编辑不会直接改动客户端拉取结果；发布后，同一 URL 在下一次拉取时返回新配置。链接代次与配置版本独立。

一个用户有 0–20 条未删除订阅；初始保留一条从旧数据迁移的「默认订阅」。每条订阅包含稳定 ID、owner、名称（1–64 字）、可选应用/用途、启用状态、独立 token 代次、已发布 revision、草稿、目标核心版本、模板来源版本、组绑定、补丁、创建/更新时间、最后成功拉取时间及最近生成错误。限额不影响既有链接；重复名称可保存，UI 必须仍能辨认具体记录。

## 页面与流程

### 订阅列表

「接入与订阅」默认展示订阅表格，主操作为「创建订阅」。表格列为名称/应用、配置来源与版本、包含节点数、状态、最近拉取、操作；节点数按唯一机器计，协议出口数在详情展示。行操作提供复制链接、编辑配置、更多菜单。

更多菜单包含预览与下载、复制为新订阅、重置本条链接、暂停/恢复、删除。URL 默认收起或掩码；用户可主动显示和复制自己的完整链接。成功复制用短 Toast 反馈，不以常驻巨大代码块占据页面。

区分「未创建订阅」「搜索无结果」「尚无可用节点」「生成失败」「已暂停」。没有节点时，仍允许创建/编辑草稿；详情说明需要管理员发布可用节点。不能把纯 direct 配置包装成正常代理订阅，也不能用空表行掩盖配置未就绪。

「可用节点」作为次级区域，展示授权、配置和最近连接状态。「代理凭据」仍为用户级操作，放在独立的次级区域，清楚说明影响所有订阅，不与单条链接重置混淆。

### 创建与复制

创建 Dialog：名称必填，应用/用途可选，选择「默认配置」或「复制已有订阅」。创建后进入完整配置编辑页，生成草稿；首次发布成功才启用下载。零节点时可保存草稿，发布按钮解释不能发布的原因。

复制只复制模板、组绑定和补丁，生成新的订阅 ID 与 token；不复用链接、不复制拉取记录。旧记录保持原样。连续点击、网络重试不会重复创建。

### 配置编辑页

完整配置编辑使用独立页面，避免把大型 JSON 编辑器挤进确认 Dialog。页头展示名称、应用、目标核心、发布状态；固定可见操作为「返回」「保存草稿」「预览并发布」。

编辑区域包含「基础配置」「节点组」「JSON Patch」三个标签；旁边提供实时生成摘要和校验结果。基础配置支持 JSON 编辑、格式化、从文件导入、恢复默认模板。恢复默认需确认会覆盖当前草稿，已发布配置不变。

节点组通过 tag 定位，不使用数组下标。每个绑定选择全部可用节点或指定机器 ID、包含协议、排除机器 ID、固定成员及默认成员。全部模式自动包含后来符合授权的节点；指定模式不会自动扩充。机器显示名称改变不改变绑定。组可独立使用不同选择，例如日常用全部节点、游戏用指定节点。

AI 和游戏组分别配套 `auto-ai`、`auto-game`，自动测速组与选择组使用同一节点集合；不能在限定游戏节点后又默认引用全局 `auto`，间接绕过该选择范围。

JSON Patch 面板包含开关、RFC 6902 编辑器、操作数、生成阶段说明和错误定位。关闭时保留补丁草稿但不应用。支持 add/remove/replace/move/copy/test 与标准 JSON Pointer 转义；不发明非标准的按 tag 路径。面向动态节点的修改应使用节点组绑定，避免依赖 `/outbounds/7` 等不稳定下标。

预览页展示本次候选完整 JSON、与当前已发布结果的差异，以及模板版本、核心版本、授权快照、节点/出口数量、补丁数量、校验时间。敏感字段默认遮蔽；主动显示或下载仅限所有者。复制/下载为可直接导入的完整 JSON，不夹带说明、平台元数据或 Markdown。

保存草稿允许存在错误；发布要求所有阻断项通过。校验失败保留用户输入，列出阶段、JSON Pointer、补丁操作序号和错误原因。并发修改或预览后授权/节点变化要求重新预览，不静默覆盖。

### 链接生命周期

| 操作 | 本条 URL | 其他订阅 | 已导入配置/代理凭据 |
| --- | --- | --- | --- |
| 发布配置 | 地址不变，下次拉取生效 | 不变 | 不主动推送到客户端 |
| 重置链接 | 旧地址立即失效，新地址保留配置 | 不变 | 已导入配置仍可连接 |
| 暂停 | 停止下载，恢复后原地址可用 | 不变 | 不撤销代理连接 |
| 删除 | 旧地址永久失效，不复用 token | 不变 | 不撤销已导入凭据 |
| 重置代理凭据 | 地址不变，后续下载使用新凭据 | 所有订阅一同更新 | 节点应用后旧凭据失效，仍受离线传播边界约束 |

重置链接、删除和重置代理凭据采用明确的确认 Dialog，标题包含操作对象，说明作用范围；成功后展示对应的新链接或状态。链接暂停/删除不能声称已远程断开设备；本期不提供每条订阅独立的代理身份、额度或在线连接统计。

## 完整配置生成契约

1. 验证订阅 token、所属账号、订阅状态、当前额度和节点授权；任何选择规则只能缩小当前账号可用集合。
2. 读取该订阅已发布的模板版本。保留用户编写的客户端静态配置；仅从当前授权快照生成 Trojan/Hysteria2 出口，tag 使用稳定机器 ID 与协议，不用显示名称或数组位置。
3. 把生成出口加入 `/outbounds`，按组 tag 展开 selector/urltest 绑定。静态成员保持显式顺序，动态成员按机器 ID、协议稳定排序，去重。不可用/被撤销的动态成员立即移除，离线但配置已发布的节点可保留并标注最后状态；不能把心跳离线等同于撤销授权。
4. 执行可选 RFC 6902 Patch。补丁可以定制完整客户端配置的非受管部分，例如 DNS、TUN、路由、规则集、日志和组设置。静态模板可定义自己的外部出口，其凭据按用户敏感配置加密；不替用户读取本机文件或请求任意地址。
5. 对最终对象执行 JSON/结构、tag 唯一性、引用完整性、组默认成员、组循环、目标版本及授权校验。受管出口的身份、地址和认证材料必须等于当前快照，禁止用模板或补丁覆盖、复制或伪造受管出口；可通过选择/组绑定排除出口。保留 `bfc_` tag 命名空间，静态模板不得占用。
6. 最终完整配置通过目标 sing-box 的解析/检查才可发布。检查器必须有版本标识、资源限制、超时和文件/网络隔离，不启动 TUN、监听端口、抓取远程 URL 或执行用户脚本。引用存在校验不等于远程规则集可达，也不等于操作系统权限或实际代理连通性，UI 分别显示这些验证范围。
7. 原子发布模板/绑定/补丁为新 revision；URL 拉取与预览使用同一生成器。每次拉取使用最新授权和凭据重新生成，不能缓存永久含密钥的完整结果。

当节点变化导致绑定为空、默认成员失效、补丁路径/test 失败或校验不通过：详情明确报错，拉取返回 422，禁止返回已撤销授权的旧配置，也禁止静默跳过补丁或回退 direct。生成器临时不可用返回 503；未知/已删除/重置的 token 返回一致的 404；已知但暂停、账号禁用或额度阻断返回 403；所有订阅响应（含错误）均 `Cache-Control: no-store`。

默认选择组空时阻断发布/下载，提示调整节点组。非默认成员撤销后可正常移除；显式默认节点撤销时要求修正默认成员，不静默改选其他节点。清晰区分「可下载」「草稿有错误」「当前生成失败」「已暂停」，最后成功拉取不表示客户端已成功应用。

## 默认模板：参考 E:\Tool\xx

参考源为 `E:\Tool\xx\config\config.json`，对应本机核心报告 `1.14.0-beta.9`，2026-09-14 读取。只提取结构和行为，不把真实服务器、密码、订阅 token、持久缓存或个人进程/应用例外放进 Figma 或公开示例。

| 参考内容 | 默认设计 |
| --- | --- |
| TUN：mixed stack、auto_route、IPv4 地址 | 桌面默认配置保留；移动端依客户端管理的 TUN 能力调整 |
| Cloudflare/Google 加密 DNS、国内 DNS、DNS 分流 | 保留策略意图，按声明的核心版本验证 evaluate/respond/race/optimistic 等字段 |
| select、auto、AI/游戏选择组 | 保留日常/AI/游戏分组，所有成员由绑定生成；不固化用户真实机器名称或推测机器地区 |
| AI/游戏的指定地区节点 | 初始使用可用节点集合；用户显式配置组成员，不把名称误认成地区授权规则 |
| 广告阻断、国内/私网直连、AI/游戏路由、Steam 国内下载 | 保留通用规则顺序；个人进程和应用包例外不纳入默认 |
| 远程 SagerNet SRS 规则集 | 保留可编辑来源；下载 detour 改为绑定的通用组，不依赖某一真实机器 |
| Clash API、缓存、日志 | 控制接口默认仅回环地址；可按应用移除不支持字段；参考的 UI 下载和缓存配置需版本校验 |
| 节点密码、地址、TLS/multiplex 参数 | 平台根据各节点已发布配置生成，不复制参考文件的真实值或 insecure 例外 |

设计附件见 [客户端模板说明](subscription-default/README.md)。附件用于评审生成规则，不应直接当作已经可运行的客户端配置；发布校验必须针对最终组装结果。模板来源和目标核心版本独立于服务器 daemon 版本。不能因面板打包 sing-box 1.14.0，就声称所有第三方客户端均支持参考 beta 配置。

用户创建时复制一个确定的默认模板版本，后续平台模板升级不静默覆盖既有订阅；「采用新版默认模板」展示差异并按草稿→预览→发布流程执行。导入外部 JSON 时扫描硬编码受管凭据，提示替换为节点绑定；不上传真实参考配置到设计服务。

## 数据、权限与迁移

新增用户级订阅记录及不可变发布版本；草稿独立持久化。既有 `subscription_tokens` 从用户级唯一改为订阅级独立代次，保留 token 摘要校验与可恢复密文。名称、模板、绑定和补丁修改采用版本检查；创建、发布、重置和删除采用幂等请求标识。

新接口族建议 `/api/v1/me/subscriptions` 及 `/:id/{draft,preview,publish,rotate,duplicate}`，资源方法处理查询、状态变更与删除；`/s/:token` 保持下载入口。具体 DTO/schema 在实现阶段制定。本轮不修改数据库迁移或 API。

迁移为每个既有用户创建一条「默认订阅」，绑定原 token、代理凭据和旧生成行为，保持原 URL 字节不变。新的参考模板通过显式更新采用，不在迁移时改变客户端 DNS/TUN/路由。迁移可重复执行而不重复创建；无 token 的用户不凭空生成公开链接。旧单订阅管理 API 在兼容期仅代理到默认记录，不能重置全部订阅。迁移前备份数据库和应用密钥。

只允许用户查看和修改自己的订阅；管理员的个人订阅视图同样按当前用户隔离，管理权限不隐含浏览其他用户订阅明文的产品入口。API Key 沿用所属账号当前策略；订阅 token 只能下载对应配置，不能调用管理接口。日志、审计和 Figma 使用掩码或虚构示例，永不记录完整 URL/token/配置密码。

## Kumo 一致性要求

全站表格使用 Kumo Table 与 LayerCard 组合；Dialog 使用 Kumo 的复合语义和官方尺寸/遮罩/操作区。不要用全局 `table/th/td`、标题或按钮样式覆盖组件默认效果。具体 token、尺寸、状态和 Figma 标注见 [设计规范](DESIGN.md)。

这些均为 `@cloudflare/kumo` 原生 npm exports，直接 import 使用。CLI 仅用 `ls`/`doc`/`ai` 阅读文档，不执行 `init`/`add` 安装组件；不因 Figma 资产搜索无结果就重写组件。Tailwind 扫描路径及样式导入顺序按官方 installation 文档验证。

适用范围包括订阅、可用节点、用户、机器、用量、Passkey、API Key 及确认/创建 Dialog。移动端表格采用可横向滚动容器或保留全部操作的列表布局；长内容不能撑破 Dialog 或遮住主要按钮。

## 验收标准

1. 同一账号创建桌面与手机两条订阅，URL 不同；修改/发布/暂停/重置/删除其中一条不影响另一条；跨账号读取与修改均失败。
2. 复制产生新身份和新 token；重复提交不重复创建。刷新后草稿和已发布版本均保留。
3. 每条 URL 输出完整 sing-box JSON；默认模板包含上述 DNS、TUN、分组、路由、规则集、缓存/日志结构，动态节点无真实参考凭据泄露。
4. 基础模板+绑定+Patch 的预览和下载结果一致；补丁增删替换与 test 失败均有覆盖，错误定位准确；关闭 Patch 后不应用但保留草稿。
5. 新增/改名/移除节点、协议变化、授权撤销和凭据轮换均以当前快照生成；不把固定数组下标误套到另一节点，不返回撤销前缓存。
6. 空组、重复 tag、悬空引用、循环引用、失效默认成员、不兼容字段和受管字段覆盖阻断发布；错误草稿不改变当前已发布结果。
7. 草稿冲突、预览过期和重复发布处理明确；生成失败、暂停、删除、无节点及最后成功拉取状态可区分。
8. 旧订阅 URL/行为迁移后保持不变；默认模板更新需要用户选择；已有导入配置的失效范围与确认文案一致。
9. Table 的默认/交替/选中/空/加载/错误状态，Dialog 的创建/危险确认/错误/提交中/长内容，以及 1440px 与 390px 视口均按官方参考进行视觉比对。
10. Dialog 背景不可交互，焦点限制在弹层内，关闭恢复触发点；Esc/遮罩行为符合语义，危险操作不因点击遮罩而执行；主要操作右对齐，取消在前。

## 一期之外

任意脚本执行、自动从远端模板 URL 抓取、Clash YAML 转换、每条订阅独立代理凭据/额度、远程控制客户端刷新、自动推断节点地理位置以及未验证的第三方客户端适配不在本期。
